Component Documentation Guidelines ​

This document is the repository-level source of truth for Component Documentation structure, layout ownership, and demo organization.

Scope ​

These guidelines apply to documentation pages under /component/. Shared Component Documentation layout rules are scoped through .component-doc-content and must not affect Guide, Home, Resource, or other non-Component pages.

Separation of Concerns ​

Component Documentation work must distinguish among:

  1. Documentation layout: Shared page hierarchy, typography, vertical spacing, section dividers, demo containers, API tables, code blocks, and page containers.
  2. Component-specific demo content: Examples, states, visual patterns, and demo-only presentation that are unique to the documented component.
  3. Component implementation: Component props, API, behavior, logic, accessibility, and implementation under packages/**.

Documentation changes must not modify component implementation unless that work is explicitly requested and separately scoped.

If the same CSS rule would also make sense on Input, Select, Checkbox, or another component page, it probably belongs to the shared Component Documentation layout rather than the individual component page.

Heading Hierarchy ​

Heading levels express semantic hierarchy only. They must not be selected to control visual size.

Documentation levelSemantic element
Page titleh1
Main Sectionh2
Subsectionh3
Nested subsection or nested API grouph4

Headings at the same level must use the same shared typography. Individual component pages must not override heading font size, font weight, or line height to create a page-specific hierarchy.

Heading levels must remain continuous. Do not skip levels for visual reasons.

Demo Group Titles ​

Labels that organize content inside a Demo are not part of the page heading hierarchy. They must not use h1–h6 and must not enter the page table of contents.

Use a non-heading element with the shared .demo-group-title class:

html
<div class="demo-group-title">Prefix Icon</div>

The shared Demo group title typography is:

css
.demo-group-title {
  font-size: 16px;
  font-weight: 600;
  line-height: 1.25;
}

Do not add local typography CSS for Demo group titles.

Vertical Spacing ​

Ordinary vertical spacing between Component Documentation content levels is 16px.

This includes:

  • Section to content
  • Heading to content
  • Parent heading to child heading
  • Subsection to the next subsection
  • Paragraph to Demo
  • Demo to the next heading
  • Documentation divider spacing, except the Main Section divider defined below
  • API heading to table
  • API table to the next heading

Do not recreate these rules in an individual component page or demo.

Main Section Dividers ​

Every Main Section h2, including the first h2, has a full-width divider above it.

The required structure is:

text
Previous content
↓ 32px
100% width divider
↓ 32px
h2 Main Section title

The divider must use the existing documentation border or divider color token. It must be generated by the shared Component Documentation layout and must not be inserted manually into component Markdown.

The 32px values are reserved for:

  • Previous content to the Main Section divider
  • Main Section divider to the h2 title

Other ordinary Component Documentation spacing remains 16px.

API Reference Hierarchy ​

API documentation follows the same semantic heading system:

API levelSemantic element
API Referenceh2
Attributes, Events, Slots, Exposes, and other API categoriesh3
Nested API grouph4

API heading-to-table and table-to-next-heading spacing are controlled by the shared 16px Component Documentation layout.

Shared and Local CSS Ownership ​

The .component-doc-content scope owns shared Component Documentation layout.

Individual component pages and demos must not add local CSS solely for:

  • Generic heading typography
  • Section or subsection spacing
  • Heading-to-content spacing
  • Generic vertical margins or gaps
  • Section dividers
  • Generic page layout
  • API layout spacing

Component-specific CSS is allowed only when it supports a visual treatment, state, behavior, or demo pattern that is genuinely unique to that component.

Examples of valid component-specific concerns include:

  • A component-specific status color
  • A component-specific state or modifier class
  • A visual pattern that exists only for that component
  • Layout required to demonstrate a component's own behavior

Shared Infrastructure Boundaries ​

Individual component pages must not rewrite shared infrastructure, including:

  • Demo card layout and internal padding
  • API table layout and cell padding
  • Code block layout and padding
  • Page container width or padding
  • Shared heading typography
  • Shared documentation spacing

Changes to shared infrastructure must be implemented in the appropriate shared documentation scope and reviewed for all Component Documentation pages.

Review Checklist ​

Before completing Component Documentation work, confirm:

  • The page uses h1, h2, h3, and h4 according to semantic hierarchy.
  • Heading levels are not used to control font size.
  • Demo group labels use .demo-group-title instead of heading elements.
  • Demo group labels do not enter the TOC.
  • Ordinary vertical content spacing is controlled by the shared 16px rule.
  • Every Main Section h2, including the first, receives the shared divider and 32px spacing.
  • The component page contains no local CSS for generic documentation typography or layout.
  • Any local CSS is genuinely component-specific.
  • Shared Demo card, API table, code block, and page container infrastructure remains untouched.
  • Guide, Home, Resource, and other non-Component pages are unaffected.
